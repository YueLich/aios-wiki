## 摘要

现代 GUI 智能体通常依赖**模型中心化的逐步交互范式**，LLM 必须在每个屏幕上重新解释 UI 并重新决定动作，这在长时域任务中非常脆弱。本文提出 **Executable Agentic Memory (EAM)**，一个结构化的知识图谱（KG），将 GUI 规划从自由形式生成转变为稳健的检索-执行过程。

EAM 的方法包括：
- **状态感知 DFS 和动作组挖掘**的记忆构建流水线，压缩多步例程
- **值引导图搜索**：轻量 Q 函数模型引导蒙特卡洛树搜索（MCTS）在 KG 上进行高效规划
- 理论上建立了 Q 模型的偏差一致性，并推导了样本复杂度边界

## 核心贡献

1. **从自由生成到检索-执行**：传统 GUI Agent 是"生成式"的（每步自由决定动作），EAM 是"检索-执行式"的（从记忆库中检索已有成功路径并执行），更加稳健
2. **状态感知记忆构建**：使用 DFS 系统探索 UI 状态空间，挖掘可复用的动作模式
3. **值引导图搜索**：用轻量 Q 函数引导 MCTS 搜索，避免在 KG 上做穷举搜索
4. **理论保证**：提供了 Q 模型偏差一致性的理论证明和样本复杂度分析

## 为什么重要

GUI Agent 的核心挑战：**跨屏幕的长时域规划**。

逐步范式的问题是：
- 每个屏幕都需要 LLM 重新理解 UI 和决定动作
- 错误会累积（一步错，步步错）
- 无法利用历史成功经验

EAM 的关键洞察：**将成功的多步交互模式压缩为可复用的记忆**。以后遇到类似情况，直接检索而不是重新规划。

## 方法详解

### 记忆构建流水线

EAM 的记忆构建分两步：

**步骤 1：状态感知 DFS**
- 从初始屏幕出发，系统性地探索 UI 状态空间
- 每个状态记录：屏幕截图、UI 元素结构、可执行动作
- 使用 DFS 确保覆盖所有可达状态

**步骤 2：动作组挖掘**
- 分析探索过程中收集的状态-动作序列
- 识别经常一起使用的动作组（如"打开设置→修改通知→返回"）
- 将动作组压缩为高层次的**动作原语**

### 知识图谱结构

EAM 的 KG 节点和边：

| 节点类型 | 描述 |
|---------|------|
| UI 状态节点 | 屏幕的结构化表示 |
| 动作原语节点 | 压缩后的动作序列 |
| 目标节点 | 任务目标描述 |

| 边类型 | 描述 |
|--------|------|
| 转移边 | 状态-动作-新状态的三元组 |
| 目标边 | 状态到目标的可达性 |
| 时序边 | 动作组内部的时序关系 |

### 值引导图搜索

给定新任务，EAM 在 KG 上执行搜索：

1. **目标匹配**：找到 KG 中与任务目标最相关的目标节点
2. **反向图搜索**：从目标节点反向搜索，找到到达初始状态的路径
3. **Q 函数剪枝**：用预训练的 Q 函数评估每条路径的预期收益，优先探索高收益路径
4. **MCTS 扩展**：对高收益但不确定的路径用 MCTS 进一步探索

Q 函数是一个轻量模型，输入是当前状态和候选动作，输出是预期累积收益。不需要 LLM 调用，适合端侧部署。

### 理论分析

论文提供了两个理论结果：

1. **偏差一致性**：如果 Q 函数是真实收益的无偏估计，则搜索算法能找到最优路径
2. **样本复杂度**：达到策略收敛所需的样本数与状态空间大小、搜索深度呈多项式关系

## 实验结果

在 Mobile/EWeb 基准上的结果：

| 方法 | 任务完成率 | 平均步数 | 成功率 |
|------|-----------|---------|--------|
| Chain-of-Thought | 67.3% | 12.4 | 58.2% |
| React | 71.2% | 11.8 | 62.7% |
| DD (Dreamer) | 74.5% | 10.2 | 68.1% |
| **EAM** | **82.6%** | **8.7** | **76.4%** |

EAM 在所有指标上都显著优于基线方法，特别是在长时域任务上优势更明显。

## 与移动端/端侧的相关性

1. **轻量 Q 函数适合端侧**：Q 函数是小型神经网络，不依赖 LLM，可完全在端侧运行
2. **MCTS + Q 函数的轻量搜索路径**：避免了昂贵的 LLM 调用推理，适合资源受限的移动设备
3. **记忆复用减少重新规划**：相似任务可以复用已有记忆，不需要每次都从头规划
4. **离线可用**：记忆构建完成后，搜索规划不依赖网络，可在离线环境运行
