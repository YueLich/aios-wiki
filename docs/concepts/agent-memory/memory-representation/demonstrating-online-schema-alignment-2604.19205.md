# Demonstrating Online Schema Alignment in Decentralized Knowledge Graphs Querying

## 论文基本信息

- **作者**: Bryan-Elliott Tam, Pieter Colpaert, Ruben Taelman
- **arXiv**: https://arxiv.org/abs/2604.19205
- **领域**: cs.DB
- **类别**: 记忆表示 → 知识图谱 → 去中心化知识图谱 → 在线模式对齐

## 摘要（翻译）

去中心化知识图谱查询（Decentralized Knowledge Graph querying）支持在无集中化数据的情况下整合分布式数据，但这种方式对词汇异构性（vocabulary heterogeneity）高度敏感。查询发起者无法切实预知所有的词汇不匹配问题，尤其是当对齐规则是局部的、有作用域的或在运行时发现的时。本文提出一种针对链接遍历查询处理（Link Traversal Query Processing, LTQP）的**在线模式对齐方法**，在查询执行期间动态发现（discover）、限定作用域（scope）和应用（apply）对齐规则，同时保持遍历行为。本文通过一个基于 Web 界面构建在基于 Comunica 的 LTQP 引擎上的去中心化社交媒体场景来演示该方法。源代码、CLI 和可复用库均已公开。演示表明，在线模式对齐能够以低开销恢复完整查询结果，为 Web 规模的 LTQP 系统提供了实用的推理基础。

## 核心贡献

1. **首个 LTQP 在线模式对齐方案**：在查询执行期间实时发现并应用对齐规则，无需预先知道词汇映射。
2. **动态作用域限定**：对齐规则被限定在特定子图或查询路径上，而非全局应用，避免错误对齐。
3. **遍历行为保持**：对齐过程不影响原始 LTQP 的遍历语义，不引入额外的中心化索引。
4. **低开销实用系统**：实现了完整的开源系统，包含 Web 界面、CLI 和可复用库。
5. **Web 规模推理基础**：为去中心化知识图谱的实用化推理提供了可扩展的技术路线。

## 研究背景与问题

### 去中心化知识图谱背景
传统的知识图谱查询依赖于集中式的数据源和统一的模式（schema）。而去中心化知识图谱（DKG）由多个独立的知识源组成，每个源有自己的词汇表和模式定义，数据分散在不同的组织/平台中。

### 核心挑战：词汇异构性
查询去中心化知识图谱时，发起查询的用户无法预知所有数据源的词汇差异。例如：
- 社交媒体数据中，"用户"可能被定义为 `foaf:Person`、`schema:Person` 或 `ex:User`
- "发布时间"可能被命名为 `created`、`published`、`postDate`

这种词汇不匹配在以下情况尤其棘手：
- **局部对齐规则**：对齐规则只适用于特定的数据源子集
- **运行时发现**：某些对齐规则只有在查询执行过程中才能被发现（如某些数据源的字段命名动态变化）

### LTQP 的特点
链接遍历查询处理（LTQP）是一种在去中心化知识图谱中执行查询的方法：
- 从一组初始数据源出发
- 通过跟随 RDF 链接逐步发现相关数据
- 不依赖全局索引，因此天然适合去中心化场景

但 LTQP 面临词汇异构性带来的查询结果缺失问题。

## 核心方法

### 在线对齐流程

**阶段一：动态发现（Dynamic Discovery）**
在 LTQP 遍历过程中，当遇到未知属性/类型时：
- 系统自动识别可能的同义词（如通过观察数据中的共现模式）
- 将候选对齐规则加入临时规则库

**阶段二：作用域限定（Scope Restriction）**
对齐规则不是全局应用的，而是限定在特定的遍历路径上：
- 只有当查询遍历经过特定数据源时，对齐规则才激活
- 这避免了跨完全不相关数据源的错误对齐

**阶段三：增量应用（Incremental Application）**
对齐规则在查询执行期间逐步应用：
- 每次发现新的对齐可能性时，查询引擎会考虑该规则
- 若应用后能恢复更多结果，则保留该规则

### 关键设计决策

1. **不依赖全局词汇映射**：避免了集中式索引，保持去中心化特性
2. **保持遍历语义**：对齐不影响链接遍历的基本行为
3. **低计算开销**：对齐计算与 LTQP 遍历并行进行，不显著增加延迟

## 为什么重要

1. **填补去中心化知识图谱查询的关键空白**：词汇异构性是 DKG 实用化的最大障碍之一，本文直接解决了这个问题
2. **保持去中心化本质**：不引入任何中心化组件，对去中心化架构友好
3. **实用的开源系统**：提供了完整可用的实现，降低了研究复现和实际应用的门槛

## 与移动端/端侧相关性

**中等相关**。知识图谱在端侧 Agent 中有应用，但本文更偏向基础设施层面：

- **端侧知识检索**：移动端 Agent 可能需要整合多个本地数据源（照片、通话记录、位置历史），去中心化查询方法有参考价值
- **隐私友好的本地推理**：去中心化方法允许数据留在本地，不上传到云端——这与端侧 AI 的隐私目标一致
- **有限资源适配**：本文的"低开销"设计对资源受限的移动设备有参考意义
