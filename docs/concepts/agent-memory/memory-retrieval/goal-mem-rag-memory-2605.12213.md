## 摘要

基于 LLM 的对话智能体在长时域交互中难以保持行为一致性。虽然 RAG 方法通过将交互存储在外部记忆模块并从中检索来克服这一限制，但其在回答复杂问题（如多跳推理、常识推理）时的效果，最终取决于智能体对检索结果进行推理的能力。

现有方法的根本问题在于：**基于语义相似性检索记忆缺乏对缺失中间事实的显式推理**，经常返回无关或不足以支持推理的证据。

本文提出 **Goal-Mem**，一个面向目标的推理框架，用于 RAG 记忆系统。Goal-Mem 不是简单地根据用户原始输入找相似内容，而是先识别查询的**目标结构**（goal structure），然后沿着目标导向的推理链逐步检索缺失的事实，确保检索到的证据能够支撑完整推理。

## 核心贡献

1. **目标结构识别（Goal Structure Identification）**：将用户查询分解为结构化的目标图，明确需要哪些中间事实
2. **目标导向检索（Goal-directed Retrieval）**：沿推理链逐步检索，每一步都以上一步的结果为条件
3. **多跳推理增强**：专门处理需要多步推理的复杂查询，填补中间事实缺口
4. **常识推理支持**：引入外部常识知识库作为补充证据源

## 为什么重要

当前 RAG 记忆系统的核心局限：**语义相似度 ≠ 推理相关性**。

例如，用户问"为什么Alice上周没有参加例会？"：
- 语义相似检索可能找到"Alice上周去出差了"，但不知道"她周四才回来"这个中间事实
- 目标导向检索会先识别"缺席原因"这个目标，然后系统性地查找"出差→返程日期→例会时间"这条推理链

Goal-Mem 解决了 RAG 系统"找到相关内容但无法支撑推理"的问题。

## 方法详解

### 目标结构建模

Goal-Mem 将每个查询建模为一个**AND-OR 图**：
- **AND 节点**：需要全部子目标都满足才能满足的条件
- **OR 节点**：满足任一子目标即可

给定查询，Goal-Mem 首先用 LLM 将其解析为 AND-OR 目标图，然后系统性地检索每个子目标的支撑证据。

### 迭代式目标导向检索

检索不是一次完成的，而是**迭代式**的：

1. **目标选择**：从当前未满足的子目标中选择最关键的
2. **证据检索**：检索能够满足该子目标的记忆片段
3. **证据评估**：判断检索到的证据是否充分
4. **子目标更新**：如果充分，标记子目标为已满足；如果不充分，继续检索或引入外部知识
5. **迭代直到**：所有必要子目标都已满足，或达到最大迭代次数

### 常识知识集成

对于常识推理问题（如"为什么下雨天人们更倾向于开车"），仅靠对话记忆是不够的。Goal-Mem 集成了外部常识知识库（如 ConceptNet、ATOMIC），在记忆证据不足时补充常识推理。

## 实验结果

在多跳问答和常识推理基准上的结果：

| 数据集 | 标准 RAG | Goal-Mem (无常识) | Goal-Mem (完整) |
|--------|---------|------------------|-----------------|
| 2-hop 问答 | 61.3% | 73.8% | 76.2% |
| 3-hop 问答 | 42.7% | 58.4% | 63.1% |
| 常识推理 | 55.8% | 62.1% | 71.5% |

Goal-Mem 在所有任务上都显著优于标准 RAG，特别是在需要多跳推理的任务上提升明显。

## 与移动端/端侧的相关性

1. **可叠加于轻量 RAG 系统**：Goal-Mem 的目标推理层可以叠加在现有轻量检索系统上，适合端侧资源受限环境
2. **减少无效 LLM 调用**：通过目标结构剪枝，避免对无关记忆的冗余 LLM 推理
3. **支持增量更新**：目标图可以增量构建，适合长期运行的端侧 Agent
