## 国产厂商专利布局特点（对比海外）

国产厂商在 OS 级行为推荐方向的专利布局明显偏向三个"中国特色"赛道：

1. **负一屏 / 智慧助手卡片生态**——华为 CN112559098B/CN112286147B/CN113225690B、vivo CN109814972B、荣耀 CN113508360B/CN117692507A，密度远超 Apple 的 Today View/Widget。
2. **跨设备协同 / 任务流转**——华为"超级终端"系 CN117632060A/CN119130396A/CN116156044B/CN115884140B 一整族，海外仅 Samsung Continuity / Apple Handoff 可比，但国产把"跨账号跨设备流转"做得更激进。
3. **应用启动预测 / 预加载**——OPPO CN119829155A/CN119781782A、荣耀 CN119127342A，把"冷启动优化 + AI 预判下一应用"做进 OS 层。

相比之下，海外 Apple/Google/Microsoft 更侧重跨生态统一账号与 Screen Time/数字健康——**国产在"数字健康/应用限额"方向反而偏少**，仅挖到 vivo CN119739440A 一条强相关。

## 各厂商密集方向

- **华为（11 条，最密集且最全面）**：跨设备协同 + 负一屏双线最粗，是唯一在"联邦学习/端侧预测"有公开 CN 专利的（CN111226238B）。
- **荣耀（9 条）**：应用推荐最密集（CN119025764A/CN119271869A/CN117668350A 三条专攻应用推荐 + 概率模型），继承华为的负一屏卡片基因。
- **OPPO（9 条）**：应用预加载/启动优化 + 服务推荐两条线都很强（CN119829155A/CN119781782A/CN119996495A 等），且较早把 LLM 记忆库引入推荐（CN119917725A）。
- **vivo（6 条）**：偏少，集中在负一屏 + 日程/上下文感知。
- **小米（5 条）**：偏少，以信息推荐 + 智能通知为主。

**国产比海外更超前的方向**：负一屏卡片化服务入口、跨设备任务流转（华为超级终端）、以及把"用户操作习惯→推荐文案"直接落到 OS 层（小米 CN121901403A）。

## 检索过程的真实障碍（重要）

- **CNIPA 官网无法自动化**：全程验证码/登录，路径 C 基本失败。
- **Google Patents XHR 接口**：仅前 2 次成功（返回结构化 JSON，含真实 CN 号 + 申请人 + 日期），随后整段出口 IP 被 503 限流，连静态专利页也被封——印证了"assignee 检索触发限流"的警告，且实际限流范围比想象更大（关键词检索也会被波及）。
- **DuckDuckGo HTML**：仅前 2-3 次返回结果后弹"鸭子验证码"。
- **PatentGuru / Espacenet**：直接 403。
- **xjishu / 爱企查**：都要人机验证。

**真正可用的是搜狗搜索**（sogou.com/web），它索引了大量金融界/网易/搜狐/今日头条"专利"专栏文章，这些文章以"国家知识产权局信息显示，XX 公司申请一项名为 YY 的专利，公开号 CNZZZ"的固定模板摘录 CNIPA 数据，一次查询可回多条真实专利号 + 标题 + 申请人 + 申请日 + 来源链接。

## 后续补全建议

1. 以搜狗为主、按"公司 + 方向关键词"分页继续挖（可再扩 20-30 条）。
2. 对已拿到的号，用人类浏览器逐条打开 `patents.google.com/patent/CN.../zh` 核验摘要与权利要求（自动化被封但人工可访问）。
3. 若需结构化批量拉取，建议申请 CNIPA / 智慧芽 / PatentGuru 的 API key 走正规数据通道，避免反复触发反爬。
